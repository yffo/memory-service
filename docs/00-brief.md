## 1. 一句话目标

给 agent 用的**通用长期记忆服务**：一个本地优先的服务，让 CLI agent（DSH / Claude Code / Codex）、IDE agent（Cursor / Cline / Zed）和自研 agent 共用同一份记忆；记忆可审计、可纠正、可带走；能调模型但默认便宜。

## 2. 为什么新起一个项目（旧项目的实测证据）

前作 `dsh-engramory-recall` 把「每轮往上下文塞几条指针」当作记忆的主要形态。它自己的账本（`.engramory-recall.jsonl`，131 轮 / 655 条指针）给出了结论：

| 证据 | 数值 | 说明 |
|---|---|---|
| 基础打开率 | **2.4%**（16/655） | 「后来被打开」的代理指标，且不能证明被写进回答 |
| 携带 ≥8 次、一次没翻开 | **23 条** | 推送的边际价值极低 |
| 库规模 | 72 篇 / 646 KB | 3 天 14 篇、14 篇、7 篇地长，其中 23 篇一次没被打开过 |
| 静默上限 | 2000 篇（`store.js:MAX_NOTES`） | 到顶新笔记静默不落盘、不报错 |
| 索引上限 | 200 行 / 25KB（硬拒写入） | 到顶后 agent 得先压缩才能记新的 |

**三个结构性缺陷**（不是画错了几笔，是纸不对）：

1. **push 是错的默认**：每轮注入固定预算的指针，命中率天生低；正确形态是让 agent 主动问（pull），只在极少数时候推。
2. **没有评测就没有方向**：整个项目从未测量「记忆是否让回答变好」，只能测「指针后来有没有被打开」。
3. **一层平铺，没有生命周期**：72 篇同质的 md 平铺，没有「身份/偏好」与「某次事件细节」的分层，没有巩固、没有遗忘、没有冲突检测 —— 久了一定腐烂。

这三条是**要修的问题**，不是**要弃的项目**。旧插件继续迭代（§10），本项目承接的是「通用、跨宿主、可推广」这条它天生做不到的线。

## 3. 目标用户与场景

- 主用户：作者本人（多宿主、多设备、长期）。
- 次用户：通过插件市场/黄页来的外部用户（他们要的是「装上就能用、别调模型也能跑」）。
- 三个必须成立的场景：
  1. **跨宿主连续**：在 DSH 里聊定的偏好，到了 Claude Code / Cursor 里依然生效。
  2. **长期不腐**：30 天后，库里 90% 以上的记忆仍然正确，且能指出哪些被新事实推翻。
  3. **成本可控**：默认档月成本接近零；开语义/巩固也只在小模型上花钱，且花多少可预期。

## 4. 非目标（第一年）

- 不做多用户/团队共享记忆（先做单用户；多设备靠同步文件夹）。
- 不做托管服务（不运营云端、不存别人的数据）。
- 不做「通用知识库/RAG 平台」（只服务 agent 的长期记忆，不替代文档检索）。
- 不追求一次接通所有宿主（MCP 是一等接口，先通 3 个宿主）。
- 不追求自动记录一切（「有话说就记」是旧项目的病）。

## 5. 成功判据（M0 的出口物，必须定量）

三条判据由 `docs/02-evaluation.md` 落地为可运行的评测。阈值在**测出基线之后**定稿（基线 = 旧插件 / 无记忆），在此之前不写产品代码。

### 判据 A：有效（记忆真的让回答变好）
- 自建任务集 ≥ 30 条，覆盖 4 类：偏好遵守、事实回忆（跨会话）、纠错（用户改过的事实必须用新的）、过程复用（上次踩过的坑）。
- 对照三档：无记忆 / 旧插件 / 新服务。
- 通过线：新服务显著优于旧插件与无记忆（具体差值与统计口径在评测文档里定；要求「显著」而不是「看起来好一点」）。
- 同时记录成本：每个任务的注入 token 与模型调用费用，**成本不得随任务数超线性增长**。

### 判据 B：可测（评测自己能活下去）
- 一次完整评测可本地一条命令跑完，时长 ≤ 15 分钟，花费 ≤ $2。
- 评测脚本进仓库、跟着 CI 跑（允许 nightly）。
- 没有这条，判据 A 会在两周内变成摆设。

### 判据 C：长效（30 天不腐烂）
- 真实使用 30 天后：被证伪的记忆（与新事实冲突且已被纠正）占比 ≤ 5%，且每条冲突都能被服务主动发现并提示。
- 库里「从未被任何路径用到」的记忆不得超过 40%（现在是 23/72 ≈ 32%，但这是 3 天的数据）。
- 任何一条记忆都能回答：**谁写的、什么时候写的、依据是什么、上次验证是什么时候**（provenance 完整性 100%）。

## 6. 架构原则（先定原则，架构文档随后）

1. **默认 pull，push 例外**：工具按需检索为主；always-on 的只有极小核心档（≤ 400 字，身份/硬偏好），且可关。
2. **分层而不是平铺**：核心档（身份/偏好）· 语义事实 · 情节事件 · 过程技能（how-to），四层各有一套写入判据与生命周期。
3. **写入有闸门**：capture → 判据（去重/冲突/价值）→ 巩固（摘要/提升为规则）；模型只在「巩固」与「冲突检测」上可选使用，默认可以用纯确定性规则跑。
4. **文件和 schema 是真相源**：默认纯文本 + frontmatter 存盘，任何时刻可 `cat`、可 git、可带走；数据库只是索引，删了能重建。
5. **预算感知的检索**：调用方给 token 预算与用途，服务端裁剪并说明裁剪了什么；混合检索（词法 + 向量）可降级到纯词法。
6. **记忆是不可信输入**：记忆内容可能被注入污染。内容以数据形式给模型，绝不拼进系统指令；写入门控保留「写入保护」这类 fail-closed 检查。
7. **成本是约束**：配置里有月预算与降级策略（超预算自动退回词法），默认档零 API 也可用。
8. **一切可观测**：每次召回/写入都能在面板或日志里回答「为什么给了它 / 为什么没给」。

## 10. 两条线怎么并行（作者 2026-10-16 定调）

> 「第一条我没有同意，**一个不变的项目没有任何意义**。」

因此本项目**不是**旧插件的替代品，而是第二条线：

| | 第一条线：`dsh-engramory-recall` | 第二条线：tabellio（仓库目录 `memory-service`，本项目） |
|---|---|---|
| 定位 | DSH 原生插件，快、可深、有真实用户 | 通用记忆服务，跨宿主、可推广 |
| 节奏 | 持续迭代，不冻结 | 调研 → 垂直切片 → 分发 |
| 长处 | 迭代回路短：改完重启就能用真库验证 | 覆盖面广：MCP 一等公民，天然跨宿主 |
| 谁先试 | **新能力优先在这里验证**（用户与真库都在） | 通用化的形态、跨宿主的账、对外分发 |

执行约定：

1. **共享内核**：存储、检索、账本、评测口径抽成一个 `memory-core` 包，两个壳（DSH 插件 / MCP 服务）都依赖它；避免两套逻辑各自腐烂。
2. **旧插件的下一期不等新项目**：先做「质量与评测」（把本项目的评测集拿去量它自己的召回），并修它已知的结构性问题 —— 2000 篇静默上限、索引到顶硬拒写入、push 打开率低（改成 pull 优先）。
3. **能力晋升路径**：旧插件里验证过的能力 → 抽进 `memory-core` → 新服务把它变成跨宿主可用的形态；新服务里先做的通用机制（如分层、provenance）也可以回灌给旧插件。
4. **发布互不阻塞**：两条线各自发版、各自 CI；共享内核的破坏性变更要同时跑两边的测试。
5. 本项目的判据 A 仍然成立：新服务要在评测上赢过旧插件 —— **赢的是长板，不是把旧插件判死**。
